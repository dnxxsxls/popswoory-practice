# Timetable — 약속시간 조율 + 모임 아카이빙 서비스 기획서

> 상태: v0.1 초안 (2026-08-20) · 작성 목적: MVP 개발 착수용 스펙
> 제품명 `Timetable`은 임시. 후보: 모여봐 / 언제모여 / 모임로그

---

## 1. 한 줄 정의

**"언제 만날지 정하고, 만난 걸 남긴다."**
소규모 내부 모임(팀·동아리·친구 그룹)이 ①가능시간을 모아 약속을 잡고 ②확정된 모임을 사진·후기·정산과 함께 기록으로 쌓아두는 웹 서비스.

## 2. 문제 정의

| 현재 | 문제 |
|---|---|
| 단톡방에서 "언제 되세요?" 를 반복 | 대화가 흘러가서 누가 언제 되는지 아무도 모름 |
| when2meet 등 외부 툴 사용 | 약속이 확정되는 순간 링크가 버려짐. 기록이 남지 않음 |
| 사진은 카톡, 정산은 토스, 후기는 노션 | 모임 하나의 맥락이 3~4곳으로 흩어짐 |
| 1년 뒤 "우리 그때 어디 갔었지?" | 검색 불가. 모임의 히스토리가 소실 |

**핵심 인사이트:** 약속잡기는 "쓰는 이유"(진입 동기)이고, 아카이빙은 "다시 오는 이유"(리텐션)다. 둘을 한 개체(Event)의 라이프사이클로 묶는 것이 이 서비스의 유일한 차별점.

## 3. 타깃 & 이용 조건

- **내부 전용.** 불특정 다수 가입 없음. 공개 검색/색인 대상 아님.
- 예상 규모: 스페이스 1~5개, 스페이스당 멤버 5~30명, 월 모임 1~10회.
- 주 사용 기기: **모바일 웹 70% / 데스크톱 30%** → 모바일 우선 설계.
- **개인정보 미수집 원칙**: 이메일·전화번호·실명·생년월일을 받지 않는다. 아이디·비밀번호로 인증하고 닉네임만 공개한다.

## 4. 핵심 개념 (도메인 모델)

```
Space (모임 그룹)          예) "수요축구", "OO팀"
 └ Member (멤버)           아이디 + 비밀번호 + 공개 닉네임. 스페이스에 소속
 └ Event (모임)            하나의 개체가 상태만 바꾸며 끝까지 간다
      polling  ──▶ confirmed ──▶ done ──▶ (archive)
      가능시간 수집   일시·장소 확정   모임 종료   사진/후기/정산
      └ Availability   (누가 언제 가능한지)
      └ Participation  (RSVP, 실제 참석 여부)
      └ Record / Photo / Expense / Comment / Tag
```

> **설계 원칙 1 — 하나의 Event가 끝까지 산다.** "약속"과 "기록"을 별도 개체로 나누지 않는다. 상태 전이만 있을 뿐이며, 덕분에 확정 즉시 아카이브 껍데기가 자동 생성된다.
> **설계 원칙 2 — 아카이빙은 강요하지 않는다.** 사진 0장·후기 0줄이어도 "언제 누구와 만났다"는 사실만으로 이미 유효한 기록이다.

## 5. 사용자 플로우

### 5.1 메인 플로우 (약속 → 기록)

```
[초대링크+접근코드]     [홈]              [만들기]           [조율]                 [확정]            [당일 이후]         [아카이브]
로그인(아이디+비밀번호) ─▶ 진행중/다가오는 ─▶ 제목·후보날짜 ─▶ 격자에 드래그로   ─▶ 추천 top3 중 선택 ─▶ 참석체크        ─▶ 타임라인·앨범
                     /최근기록          ·시간범위·소요    내 가능시간 표시       주최자가 확정       사진·후기·정산      ·검색·통계
                                        ·마감시각         히트맵 실시간 갱신     상태 confirmed      상태 done
```

### 5.2 참여자 최소 동선 (가장 중요한 지표)

링크 클릭 → 아이디·비밀번호 입력 → 격자 드래그 → 자동 저장. **목표: 30초 이내, 화면 전환 2회 이하.**
학기 시간표를 한 번 등록해둔 멤버는 수업 시간이 이미 잠겨 있으므로 실질 20초.

### 5.3 상태 전이 규칙

| 전이 | 트리거 | 부수 효과 |
|---|---|---|
| polling → confirmed | 주최자가 시간 확정 | 참여자 RSVP 자동 `going`(가능 표시자), 아카이브 스켈레톤 생성 |
| confirmed → done | 종료시각 +3h 경과 시 자동, 또는 수동 | 홈에 "기록 남기기" 카드 노출 (7일간) |
| any → cancelled | 주최자 취소 | 사유 기록, 아카이브에는 취소 이벤트로 남김 |
| polling 마감 초과 | 마감시각 경과 | 홈 상단에 "확정 필요" 배지, 응답 입력은 계속 허용 |

## 6. 기능 명세

### 6.1 인증 / 스페이스 (P0)

- 스페이스 접근: `초대 링크(/join/[slug]) + 접근코드` 1회 입력 → 아이디 확인 → 비밀번호 설정·확인 → 닉네임 설정.
- 재방문: 아이디 + 비밀번호. 세션 쿠키 30일 유지(기기 기억).
- 비밀번호 분실 → 관리자가 `/members`에서 임시 비밀번호 `0000`으로 초기화. 기존 세션은 모두 끊고, 사용자는 로그인 후 내 정보에서 8자 이상의 새 비밀번호로 변경.
- 관리자(admin): 멤버 추가/비활성화/역할 변경, 접근코드 변경, 이벤트 강제 수정·삭제.
- **수집하지 않는 것**: 이메일, 전화, 실명, IP 장기보관, 서드파티 트래커.

### 6.2 약속 조율 (P0) — 핵심

**생성 (3단계 위저드)**
1. 제목 / 설명(선택) / 장소 후보(선택)
2. 후보 날짜 선택(캘린더 다중 선택, 최대 14일) + 하루 시간 범위(기본 09:00–24:00) + 슬롯 단위(30분 기본, 15/60 선택)
3. 필요 소요시간(기본 2시간) + 응답 마감시각 + 필수 참석자 지정(선택)

**응답 화면 (Availability Grid)**
- 세로축 시간 / 가로축 날짜. 모바일은 가로 스크롤 + 날짜 3일씩 스냅.
- 드래그로 칠하기, 다시 드래그로 지우기. **2단계 강도**: `가능(연한 색)` / `무조건 가능·선호(진한 색)`.
- 입력 즉시 낙관적 반영 + 디바운스 저장(자동 저장, 저장 버튼 없음).
- 하단 히트맵: 슬롯별 가능 인원수 색 농도. 슬롯 탭 시 **가능한 사람 / 불가한 사람 이름 목록**.
- 보조 기능: `지난주와 동일` 복사, `평일 저녁만` 빠른 선택, 응답 현황 배지(7명 중 4명 응답).
- **내 고정 일정(시간표) 자동 반영**: 수업 시간대는 회색 빗금으로 잠긴 채 렌더 → 나머지 안에서만 고르면 된다. 설계 상세는 [FEATURE-timetable-import.md](FEATURE-timetable-import.md).

**추천 알고리즘**
```
슬롯 s의 점수 = Σ_members w(level) × r(member)
  w(가능)=1.0, w(선호)=1.4
  r(필수참석자)=2.0, r(일반)=1.0
연속 duration_minutes 만큼의 윈도우 합계 상위 3개를 추천
동점 시: ① 필수 참석자 전원 가능 → ② 불참 인원 적은 순 → ③ 이른 날짜 순
각 후보에 "불참: 홍길동, 김철수" 명시 (누가 빠지는지 숨기지 않는다)
```

**확정**
- 주최자/관리자만. 추천 카드 클릭 or 직접 지정 → 장소·메모 입력 → 확정.
- 확정 카드에 캘린더 담기(.ics 다운로드), 링크 복사, 지도 링크.

### 6.3 확정 이후 (P0)

- RSVP: 참석 / 불참 / 미정 (사유 한 줄 선택).
- 준비물 체크리스트(간단 todo, 담당자 지정) — P1.
- D-day 홈 상단 고정 카드.

### 6.4 아카이빙 (P0~P1)

| 기능 | 우선순위 | 설명 |
|---|---|---|
| 참석자 확정 | P0 | RSVP와 별개로 "실제 참석" 체크. 통계의 기준값 |
| 사진 업로드 | P0 | 다중 업로드, 클라이언트 리사이즈(장변 1600px, webp), 썸네일 그리드, 라이트박스 |
| 후기/메모 | P0 | 멤버 누구나 여러 개 작성 가능(짧은 글 + 사진 인용). 마크다운 아님, 플레인 텍스트 + 줄바꿈 |
| 태그 | P1 | `#등산 #연말 #서울` 자유 태그. 자동완성 |
| 정산 | P1 | 지출 항목(항목명·금액·결제자) → 참석자 1/N 또는 지정 분배 → 인당 정산표 출력. **송금 연동 없음**, 계산과 기록만 |
| 댓글/리액션 | P2 | 기록에 대한 한 줄 반응 |

**아카이브 뷰**
- **타임라인**(기본): 최신순 카드. 날짜·제목·대표사진·참석자 아바타·태그.
- **캘린더**: 월간 그리드에 모임 점 표시.
- **앨범**: 사진만 모아보기(모임 구분선).
- **검색/필터**: 제목·후기 전문 검색, 태그·참석자·기간 필터.

### 6.5 통계 (P2)

스페이스 대시보드: 연간 모임 횟수, 월별 빈도 막대, 멤버별 참석률, 최다 동반 참석 페어, 누적 지출.

### 6.6 알림 (P1)

개인정보를 받지 않으므로 **개인 채널(이메일/SMS/카톡) 발송은 하지 않는다.**
- 웹 푸시(브라우저 구독, 선택) — 새 약속 생성 / 마감 12시간 전 미응답 / 확정 / 기록 요청
- 그룹 채널 웹훅(슬랙·디스코드) — 스페이스 관리자가 URL 등록 시 동일 이벤트 전송
- 인앱: 홈 상단 액션 배너 (알림 없이도 동작하는 것이 기본)

## 8. 비기능 요구사항

- **성능**: 조율 화면 LCP < 2.0s(4G), 격자 드래그 60fps, 응답 저장 반영 < 300ms(낙관적 UI).
- **모바일**: 최소 375px 폭 지원. 터치 드래그 시 스크롤 잠금 처리 필수.
- **접근성**: 색만으로 가능/불가를 구분하지 않음(농도 + 숫자 병기). 키보드로 격자 입력 가능(방향키+스페이스).
- **오프라인/불안정 네트워크**: 응답 입력은 로컬 큐에 쌓고 재전송.
- **다크모드**: 지원.

## 9. 개인정보 · 보안 정책

1. 수집 항목은 `로그인 아이디`, `비밀번호 해시`, `닉네임(가명 가능)`, `작성 콘텐츠(사진·글)`뿐. 이메일/전화/실명 없음.
2. 사진에는 얼굴이 포함될 수 있으므로 **모든 파일은 비공개 버킷 + 단기 서명 URL**로만 제공. 공개 URL 미발급.
3. 접근코드·비밀번호는 해시 저장한다. 비밀번호 시도 rate limit은 5회/10분, 아이디 기준이다.
4. 탈퇴/삭제: 멤버 비활성화 시 표시명은 `탈퇴한 멤버`로 마스킹, 작성 사진·글은 관리자 판단으로 삭제 가능.
5. 보관 정책: 기본 무기한 보관, 스페이스 설정에서 "N년 경과 사진 자동 삭제" 옵션(P2).
6. 검색엔진 색인 차단(`robots.txt` + `noindex`).
7. 외부 분석 도구·광고 SDK 미탑재.

## 10. 범위 밖 (Non-goals)

- 공개 커뮤니티, 회원 모집, 외부 검색 노출
- 실시간 채팅 (단톡방을 대체하지 않는다)
- 실제 송금·결제 연동
- 캘린더 양방향 동기화(구글/애플) — .ics 내보내기까지만
- 네이티브 앱 (PWA 설치로 대체)
