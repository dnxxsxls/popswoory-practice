# 확정 스코프 v1 — 8명 / 2개월 실사용 기준

> 이 문서가 [PRD.md](PRD.md)의 로드맵보다 **우선**한다. PRD는 기능의 전체 지도이고, 이 문서는 실제로 만들 것의 목록이다.
> 전제: 이용자 7~8명, 운영 기간 1~2개월, 확장 계획 없음, 모바일 웹 중심.

---

## 1. 이 규모에서 달라지는 것

원래 PRD는 "여러 스페이스 × 수십 명 × 지속 운영"을 가정해 5주 분량으로 짜여 있었다. 8명이 2개월 쓰는 도구에는 과설계다. 아래는 **의도적으로 잘라낸 것**들이며, 필요해지면 언제든 복원할 수 있도록 삭제가 아니라 보류로 표시한다.

| 기능 | 판정 | 이유 |
|---|---|---|
| 멀티 스페이스 | **컷** | 스페이스 1개 고정. `space_id`는 스키마에 남기되 값은 하나 |
| 접근코드 2중 인증 | **축소** | 초대 링크 + 아이디·비밀번호로 충분. 서로 다 아는 8명 |
| 정산(1/N 계산) | **보류** | 토스로 하면 된다. 2개월간 필요해지면 그때 추가 |
| 태그 · 전문검색 | **컷** | 2개월이면 모임 10회 내외. 스크롤로 다 보인다 |
| 통계 대시보드 | **컷** | 표본이 없다 |
| 캘린더 뷰 / 앨범 뷰 | **컷** | 타임라인 하나면 충분 |
| 웹푸시 · 슬랙 웹훅 | **보류** | 링크를 단톡방에 던지는 게 더 빠르다 |
| 준비물 체크리스트 | **컷** | |
| 댓글 · 리액션 | **컷** | |
| 보관 정책 · 자동 삭제 | **컷** | 2개월 뒤 통째로 내리면 된다 |

**결과: 5주 → 약 2.5주.**

## 2. 핵심 경로 재정의 (가장 큰 변경)

> **"전원 공강 시간대 자동 계산"이 부가 기능이 아니라 이 서비스의 메인이다.**

원래 계획에서 시간표 임포트는 M5(맨 마지막)였다. 그런데 8명 전원의 시간표가 등록되면 **아무도 응답하지 않은 상태에서 이미 후보 시간이 나온다.** 이건 격자 드래그를 보조하는 기능이 아니라, 격자 드래그를 대부분 불필요하게 만드는 기능이다. **M2로 승격한다.**

### 2.1 3레이어 격자

2번 결정("시간표로 자동 '가능' 확정 금지")과 5번 요구("전원 공강 자동 제안")는 충돌하지 않는다. **제안과 확정을 분리**하면 된다.

| 레이어 | 의미 | 표시 | 확정 근거로 |
|---|---|---|---|
| 🔒 **잠김** | 누군가 수업 중 | 회색 빗금 | 쓰이지 않음 |
| 🟡 **후보** | 전원 공강 — 단, 아무도 확인 안 함 | 연한 노랑 | **쓰이지 않음** |
| 🟢 **확인됨** | 멤버가 직접 "가능" 표시 | 진한 초록 | ✅ 유일한 근거 |

시간표는 🟡까지만 만든다. 🟢은 사람만 만들 수 있다. **확정 버튼은 🟢 기준으로만 동작**하고, 미확인 멤버가 있으면 "3명 미확인" 경고를 띄운다.

### 2.2 응답 UX — 전체 격자를 칠하지 않는다

전원 공강 구간이 이미 계산되어 있으므로, 응답자에게 24시간 격자를 다 보여줄 이유가 없다.

```
[기존]  09~24시 × 7일 = 210칸을 드래그
[변경]  겹치지 않는 전원 공강 후보를 모두 카드로 표시 → 모든 카드에 O / X 응답
        └ 부족하면 [전체 격자에서 직접 고르기]로 폴백
```

8명 규모에서는 공강 교집합이 하루 몇 구간으로 좁게 나오므로, 가능한 후보를 시간순으로 전부 보여주고 **모든 후보에 답해야 저장**하게 한다. 모바일에서 드래그 제스처를 최소화하는 것이 이 규모의 핵심 UX다. 전체 격자는 폴백 경로로만 유지한다(공강이 0개일 때 필요).

> 이 변경으로 [ARCHITECTURE.md](ARCHITECTURE.md) §8의 리스크 1순위였던 "모바일 드래그 UX"가 크게 완화된다. 다만 격자 자체는 폴백과 시간표 검토 화면에 여전히 쓰이므로 없애지는 않는다.

## 3. 온보딩 — 시간표는 가입할 때 한 번만 (확정)

시간표 등록을 나중으로 미루면 절반은 안 올린다. **한 명만 빠져도 "전원 공강" 계산이 무의미해지므로, 가입 플로우 안에 넣는다.**

```
초대 링크
  └ ① 아이디 입력
       ├ 기존 회원 → 비밀번호 입력 → 로그인
       └ 신규 회원 → 비밀번호 2회 입력 → 닉네임 설정
  └ ② 시간표 등록  ← 여기, 딱 한 번
        시간표 캡처 올리기 ─▶ 크롭 ─▶ 자동 인식 ─▶ 검토·수정 ─▶ 저장
        또는 [직접 입력]  ─▶ 격자에 드래그
        또는 [나중에]     ─▶ 건너뛰되 홈 상단에 상시 배너
  └ 완료 → 이후 모든 약속에 자동 반영. 다시 올릴 일 없음
```

- **한 번 등록하면 끝.** 약속을 만들 때마다 올리는 게 아니라, 계정에 붙어서 계속 남는다.
- 수정은 `설정 → 내 시간표`에서 언제든(수강 정정, 휴강 반영). 수정하면 **진행 중인 모든 약속에 즉시 반영**된다.
- **[나중에]를 허용하되 눈에 띄게 한다**: 미등록 멤버는 공강 계산에서 "제약 없음"으로 처리되고, 후보 카드에 `시간표 미등록 2명` 배지가 붙는다. 계산이 조용히 틀리는 것보다 낫다.
- 2개월 단발성 운영이므로 학기·유효기간 개념은 두지 않는다(`valid_from/until`은 스키마에만 남기고 미사용).

## 4. 만들 것 (확정 목록)

### M1 — 기반 + 온보딩 (3일)
- Next.js + Supabase + Vercel 배포, 모바일 레이아웃 셸, PWA 매니페스트
- 초대 링크 → 아이디 → 비밀번호 → 신규 회원은 닉네임 설정 → 세션 쿠키
- 위 온보딩 3단계 골격 (시간표 단계는 M2에서 채움)
- 멤버 목록 + 관리자 비밀번호 초기화(임시 비밀번호 `0000`)

### M2 — 시간표 (4일) ★ 핵심
- `member_schedules` / `member_schedule_blocks` 스키마
- 온보딩 ③단계 구현: 업로드 → **크롭(건너뛰기 불가)** → VLM 추출 → **검토 화면에서 수정** → 저장
- 직접 입력 폴백(격자 드래그) + `설정 → 내 시간표` 수정 화면
- "우리 팀 주간 공강표" 화면 — 8명 시간표 교집합을 한 장으로

### M3 — 약속 잡기 (4일)
- 약속 생성: 제목 + 날짜 범위 + 소요시간 (그게 전부)
- 전원 공강 후보 자동 산출 → O/△/X 응답 카드
- 폴백 격자 + 히트맵
- 확정(🟢 기준) → .ics + 링크 복사

### M4 — 아카이빙 (3일)
- 참석 체크 (확정 멤버 기본 선택)
- 사진 업로드 (다중, 클라이언트 리사이즈, 비공개 버킷 + 서명 URL)
- 한 줄 후기
- 타임라인 목록 + 상세

### M5 — 마감 (2일)
- 홈 대시보드 (응답 필요 / 다가오는 / 기록 대기)
- 실기기 점검, 에러 처리, robots noindex

**합계 약 16일 = 2.5주 (여유 포함 3주)**

## 6. 시간표 이미지의 외부 전송 — 최종 판단

**셀프호스팅으로는 해결되지 않는다.** 앱이 어디서 돌든 VLM 추론 요청은 OpenAI 서버로 나간다. 외부 전송을 0으로 만드는 유일한 방법은 로컬 비전 모델 구동인데, 한국어 시간표 인식 정확도와 하드웨어 요구를 감안하면 8명·2개월 규모에서는 과투자다.

**채택하는 해법: 전송되는 내용을 줄인다.**
1. 업로드 플로우에 **크롭 단계를 필수로** 넣는다 (건너뛰기 불가). 기본 크롭 영역은 상단 헤더를 제외한 격자 부분으로 미리 잡아준다.
2. 안내 문구: "이름·학교가 나온 부분은 잘라내고 올려주세요. 시간표 격자만 있으면 됩니다."
3. 이미지는 서버 메모리에서만 처리하고 저장하지 않는다. 에러 로그에 base64가 남지 않도록 마스킹.
4. 결과적으로 나가는 정보는 "색 블록 + 과목명 + 시간 격자"뿐 — 서로 다 아는 8명이 공유하는 정보 수준.

비용: 8명 × 1회 ≈ **$0.4 (약 600원)**. 재업로드를 감안해도 1,000원 미만.

## 7. 컷하지 않은 것 — 이유

- **아카이빙**: 이 서비스의 원래 목적이다. 2개월간 모임 5~10회의 사진과 기록이 남는 것 자체가 산출물이다.
- **아이디·비밀번호 로그인**: 8명이어도 "누가 썼는지"는 구분되어야 한다. 사진과 후기에는 별도 닉네임이 붙는다.
- **폴백 격자**: 공강 교집합이 0개로 나오는 주가 반드시 생긴다. 그때 폴백이 없으면 서비스가 멈춘다.
